# conhecimento/desenvolvimento/specs/

Specs de desenvolvimento, organizadas em pacotes do tamanho de uma feature, que agrupam várias User Stories — geradas pela skill `create-spec` a partir de um briefing funcional (`intent`), com ou sem um artefato visual/protótipo já construído (HTML, React ou similar). Cada US dentro da Spec vem com comportamento detalhado, campos, estados de tela, ações e destino técnico, critério de aceite e um bloco YAML pronto para ser enviado a uma IA de desenvolvimento — além das Perguntas Abertas levantadas pela etapa de sabatina, quando faltar informação para o desenvolvimento começar.

## Convenção de arquivos

`spec-[slug-da-feature]-[YYYY-MM-DD].md`

Cada arquivo contém uma ou mais Specs (`## SPEC-N`), cada uma com cabeçalho (objetivo, US incluídas, ordem de implementação, regras transversais, dependências, fora de escopo, status) e, por US (`### US-N.M`): história no formato padrão, referência (protótipo ou seção do briefing), comportamento detalhado, campos e dados, estados de tela, ações e destino técnico, regras de negócio aplicáveis, fora de escopo, critério de aceite, Perguntas Abertas e o bloco YAML estruturado — nas seções definidas pela skill `create-spec`.
